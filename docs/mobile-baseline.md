## 已知的量測限制

- 手勢、下拉重新整理、觸覺回饋無法在自動化環境驗證。
- 自動化分頁無法捲動最上層文件，頁面捲動相關行為只能靠 iframe 量。
- 無法偽裝 User-Agent，iOS 專屬分支只能靠單元測試涵蓋。

## 封面接管之後（2026-08-26）

`npm run covers` 把封面抓下來、縮成兩種尺寸、輸出三種格式，
畫面改用 `<picture>` 依瀏覽器挑格式。

| | 之前 | 之後 | |
|---|---|---|---|
| 滑完整份圖鑑的圖片流量 | 27.3 MB | **0.60 MB** | −98% |
| 單張清單縮圖 | 平均 537 KB | **平均 12 KB** | AVIF |
| 詳情頁大圖 | 平均 537 KB | 平均 45 KB | AVIF |
| 超過 40 KB 的縮圖 | 48 / 52 | **0 / 51** | |

退化路徑：AVIF → WebP（19 KB）→ JPEG（20 KB）。
最舊的瀏覽器拿到 1.0 MB，仍比原本少 96%。

量測方法：接管前的 27.3 MB 是逐一下載 58 個外連網址實際加總；
接管後是本地檔案大小加總。**不是**用瀏覽器的 `transferSize` ——
那個對跨網域資源一律回報 0，會嚴重低估。

已在瀏覽器驗證格式協商正確（Chrome 151 取到 `001-sm.avif`，420px 寬）。

> 還有 7 張抓不到（6 張失效 + 1 張逾時），清單在 `docs/covers-failed.json`。
> 那些會退回原本的外連網址，載不出來時顯示設計過的替代封面而不是灰色破洞。
