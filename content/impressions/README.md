# 手寫的那一層

一場活動一個檔案，檔名是**永久鍵 ID**：`043.md` 對應 ID 43。
`npm run impressions` 會把這裡的內容折進 `src/data/events.json`
（`npm run build` 也會自動跑），網站就吃得到。

```markdown
---
一句話: 兩團第一次在台灣同台，四月的大佳河濱。
票價: 搖滾區 3800 / 座位區 2800
售票狀況: 開賣 3 分鐘完售
---

心得寫在這裡。支援 **粗體**、*斜體*、`行內碼`、[連結](https://example.com)、
清單、`>` 引言、`---` 分隔線。

## 曲目
1. STAR BEAT!〜ホシノコドウ〜
2. 天下トーイツ A to Z☆
安可
Returns

## 場刊
聲優訪談
台北公演特別寫真
```

## 哪些欄位寫在這裡

**前置資料**（一行一個）：`一句話`、`簡介`、`票價`、`售票狀況`、`主視覺`、`系列`

**`## 小標`**（一整串的）：`曲目`、`周邊`、`場刊`

**第一個小標之前的正文** ＝ 心得。

只寫其中幾樣、或什麼都不寫，都可以。
全空的檔案會被當成「待補」跳過，不會覆蓋既有內容。

## 檔名綁的是 ID，不是編號

`043.md` 對應的是 **ID 43**，不是 `#043`。
兩者現在是分開的：編號（`#042`）是圖鑑上的顯示序號，可以隨你重排；
ID 是永久鍵，照片、心得、打卡備份碼、分享網址全都綁它，給了就不能再動。

所以**在 Sheet 中間插一列、重排編號，這裡的檔案不會跟著錯位**。
（Sheet 還沒有 `ID` 欄的話會退回用編號，那時候才要小心。）

## 什麼該寫在這裡、什麼該寫在 Sheet

**先講最重要的差別：Sheet 是即時的，這裡不是。**

Sheet 改完，下次開網頁就生效 —— 不用部署，手機上也能改。
這裡的檔案要：改檔 → `npm run impressions` → commit → push → 等 Vercel 建置。

所以：

| 情況 | 寫在哪 |
|---|---|
| 演唱會剛散場，想馬上把曲目記下來 | **Sheet**。格子裡按 `Alt+Enter` 就能換行，多行完全沒問題 |
| 坐在電腦前慢慢寫幾百字的心得 | **這裡**。編輯器比儲存格好寫太多，而且進 git 看得到修改歷程 |
| 日期、地點、人物、樂團、封面 | **Sheet**。那是結構化資料，試算表本來就擅長 |

兩邊都填的話**這裡優先** —— 這裡是建置時後折進去的。
所以同一欄不要兩邊都寫，會覺得「Sheet 改了怎麼沒變」。

> Sheet 的多行格子有測試守著（`tests/archive.test.mjs`）——
> 整個歌單功能都靠那個 round trip，解析器哪天不吃多行，
> 曲目會整批擠成一行，而畫面上只會看起來像「這場只有一首歌」，不會報錯。

## 有一個更省事的入口

`npm run dev` 之後開 `/__fill`：一次一筆，旁邊放齊寫這句話需要知道的東西
（封面、日期、場館、誰來了、這是第幾次、距上一場多久）。
填曲目時還會列出已經打過的歌名，點一下就補進去 —— 寫法才會一致。
